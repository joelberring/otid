# AGENTS.md

## Project mission

Build O-Tid: an offline-first, internet-based orienteering timing and route-analysis system with direct SPORTident hardware support.

The system must remain usable at a readout station when the internet or server is unavailable. Raw hardware data must be preserved and all server ingestion must be idempotent.

## Read first

Before changing code, read:

1. `CODEX_BRIEF.md`
2. `docs/architecture.md`
3. `docs/domain-rules.md`
4. `docs/offline-sync.md`
5. the most specific `AGENTS.md` in the directory being changed

When documents disagree, stop and record the conflict in `docs/status.md`; do not silently invent a third architecture.

## Non-negotiable architecture rules

- `packages/domain` is pure TypeScript and performs no I/O.
- Result logic must not live in React components, route handlers, database triggers, or SQL views.
- Raw SPORTident messages are immutable.
- Every ingest endpoint is idempotent.
- Result changes create revisions; they never overwrite history.
- External Eventor or IOF objects are mapped into the internal model at adapter boundaries.
- Maps, routes, uploaded files, and API keys are private by default.
- The readout workflow must have an explicit offline path.
- Avoid microservices, Redis, Kubernetes, GraphQL, and serverless-only design unless an accepted ADR requires them.
- Do not add a dependency merely to avoid writing a small deterministic function.

## Licensing and external source rule

MeOS and Oxygen are AGPL-3.0 projects.

Unless `docs/adr/ADR-licensing.md` explicitly approves AGPL reuse:

- do not copy code,
- do not translate or port code,
- do not reproduce class/file structures,
- do not paste snippets into comments or tests,
- use external systems only as behavioral references and interoperability targets,
- write independent specifications and tests,
- record factual research sources in `docs/research`.

Do not use, scrape, or depend on Livelox maps or routes. Do not copy Livelox UI or branding.

## SPORTident rules

- Keep raw byte transport separate from protocol parsing.
- Keep protocol parsing separate from card normalization.
- Keep card normalization separate from result evaluation.
- Every parser change needs fixtures for arbitrary chunk boundaries, bad CRC, duplicate frames, and truncation.
- Never claim hardware support that has only been tested against synthetic bytes.
- Mark each card/station combination as `untested`, `captured`, `decoded`, or `field-verified`.
- Do not log names or unnecessary personal data in serial debug logs.

## Database rules

- Schema changes require a migration and rollback/restore note.
- Use optimistic concurrency or explicit version checks for user-editable competition data.
- External IDs are never primary keys.
- Avoid destructive migrations. Use expand/migrate/contract for production data.
- Tests must use PostgreSQL, not a SQLite substitute for server behavior.
- PostGIS-specific behavior needs integration tests.

## API and sync rules

- Validate all request and response contracts.
- Batch requests carry device ID, sequence range, package version, and content hashes.
- A retry must be safe.
- Server acknowledgements identify what is durably stored.
- A client must never delete the only local copy because a network request was sent.
- SSE events have monotonic IDs and reconnect behavior.

## UI rules

- Swedish is the first UI language; keep text externalized for later translation.
- Optimize operative screens for touch, rain, glare, stress, and gloves.
- Readout screens use large status areas and minimal navigation.
- Do not hide critical state behind color alone.
- Show internet state, hardware state, package version, and local queue size.
- Public pages work without login.
- Avoid ornamental animation.
